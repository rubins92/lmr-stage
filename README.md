# lmr-stage — Lumir Landing Staging

Совместный стейджинг лендинга **lumir.photo**. Редактируем здесь через Claude Code, апрувленные правки Сергей переносит в прод вручную.

## Что внутри

- `index.html` — единственная страница лендинга
- ассеты: `favicon.*`, `hero-banner-*.png`, `logo-lumir-photo.png`, `flow-*.mp4`
- `.claude/CLAUDE.md` — инструкции для Claude Code

## Стек

Чистый **HTML + Tailwind CDN + ванильный JS**. Никакой сборки, никакого npm. Один файл `index.html` с inline-стилями и скриптами.

## Как работать (3 шага)

### 1. Клонируешь

```bash
git clone https://github.com/rubins92/lmr-stage.git
cd lmr-stage
```

### 2. Запускаешь Claude Code и поднимаешь превью

```bash
claude
```

В Claude Code попроси:
> Запусти превью на localhost

Или сам в терминале:
```bash
npx serve .
```
→ открой `http://localhost:3000` в браузере. Превью обновляется при перезагрузке страницы.

### 3. Правишь и пушишь

```bash
git add .
git commit -m "коротко что поменял"
git push
```

Сергей увидит изменения в GitHub, ревьюнет и при апруве перенесёт в прод.

## Конвенции

- **Коммит-сообщения** — кратко на русском или английском, по делу. Примеры: `update hero copy`, `fix mobile spacing section 3`, `replace section-2 image`.
- **Текст на лендинге — только русский.**
- **Ассеты** — клади в корень папки, как `hero-banner-final.png`. Без подпапок.
- **Большие видео (>20 МБ)** — НЕ пушь. Пришли Сергею отдельно.
- **Не трогай** `.claude/CLAUDE.md` — это инструкции для Claude Code.

## Что делать НЕ нужно

- Не делай Pull Request — пушь прямо в `main`. Доверяем друг другу, ревью делает Сергей перед прод-деплоем.
- Не настраивай CI / GitHub Actions — деплой ручной у Сергея.
- Не удаляй файлы без согласования.

## Если сломал — откатись

```bash
git log --oneline -10           # найди коммит до поломки
git revert <sha>                # откатить один коммит
git push
```

Или скажи Сергею — он откатит.

## Витрина шаблонов `shablony.html` (ветка `templates-shop`)

Отдельная SEO-страница «Шаблоны выпускных альбомов»: более 25 бесплатных дизайнов Lumir и 43 платных шаблона студии Мироновой (аренда 390 ₽, покупка). На главной на неё ведут пункт «Шаблоны» в шапке, кнопка «Больше дизайнов» в разделе 02 и ссылка в подвале.

**Файлы:** `shablony.html`, `shablony.md` (текстовая версия для ИИ-поиска, на неё ссылается `<link rel="alternate">`), `assets/templates/` (CSS, JS, картинки дизайнов Lumir, `og-shablony.jpg`), `assets/mironova/`, на главной ещё `assets/banners/fm-*.jpg` (баннер раздела 03) и `assets/banners/og-main.jpg` (превью ссылки). Обновлены `sitemap.xml` (страница и картинки), `robots.txt`, `llms.txt`.

**Что нужно в `promote.sh` перед деплоем** (сейчас он обрабатывает только `index.html`):
1. копировать `shablony.html` и `shablony.md` в `production/`;
2. выпрямлять пути в `shablony.html` так же, как в `index.html`: `assets/templates/X`, `assets/mironova/X` → `X`;
3. включать аналитику и в `shablony.html` (`ANALYTICS_ENABLED` false → true);
4. копировать `assets/templates/*` и `assets/mironova/*` плоско. Имена уникальные, с остальными ассетами не пересекаются (проверено).

Абсолютные ссылки (og:image, JSON-LD, sitemap) уже записаны в плоском виде: `https://lumir.photo/<файл>`.

**Видео в hero:** теперь `assets/lumir-season-v3.mp4` («Весь сезон», 60 сек). В git его нет, файл передаётся отдельно.

**Как собирается витрина:** `shablony.html` генерируется скриптом из `index.html` (шапка, подвал, стили, аналитика, тема) и каталога шаблонов. Скрипты пока лежат у Лизы локально. Если меняешь меню или подвал главной, витрину нужно пересобрать (попроси Лизу) или поправить те же места в `shablony.html` руками.
